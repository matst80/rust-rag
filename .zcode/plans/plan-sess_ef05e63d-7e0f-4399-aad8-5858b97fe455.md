# Reorganize the wiki "Unorganized" experience into a three-pane organize workspace

## Problems (confirmed in code)
- `components/wiki/graph-tree.tsx` renders 12px `text-xs` rows with 9px badges in a 22%-wide sidebar, capped at 300 items — most entries have no graph edges, so they all render as flat leaf rows with disabled chevrons ("no expand"), filling the whole sidebar.
- The sidebar is a **mode toggle** (Sources XOR Unorganized), so the structured tree isn't even visible while dragging from the inbox — you can't see a target.
- No preview of entry content anywhere in the flow.
- Native HTML5 drag with browser-default ghost — nothing tells you *what* is being moved.
- **Bug**: `hooks/use-wiki-move.ts` invalidates string keys (`"entries-paths"`, `` `entries-tree-...` ``) but the hooks use array keys (`["entries-paths", src]`, `["entries-tree", src, prefix]` — `lib/api/hooks.ts:164,171`). After every move, the structured trees go stale.

## Layout (per your choices: three panes, single-move DnD)

`entry-tree.tsx` becomes a 3-panel `ResizablePanelGroup` (desktop):

```
┌ INBOX (26%) ┬ WIKI TREE (22%) ┬ CONTENT (rest) ┐
│ filter, ±   │ sources/folders │ folders grid,  │
│ entry rows  │ (drop targets)  │ entry articles │
│─────────────│                 │                │
│ PREVIEW     │                 │                │
└─────────────┴─────────────────┴────────────────┘
```

Inbox panel is collapsible to a slim "Show inbox (N)" rail. Mobile keeps today's drawer for the tree; the inbox opens as a Sheet; on touch/keyboard, each row gets a "Move to…" action opening a Dialog with the existing `WikiPathTreePicker` (DnD fallback).

## Changes

### 1. New `lib/drag-entry.ts` — shared drag payload
`setEntryDragData(dt, {id, source_id, path, title})` / `readEntryDragData(dt)` replacing the copy-pasted `application/json`+`text/plain` parsing in `graph-tree.tsx`, `entry-tree.tsx`, `wiki-tree-node.tsx` (and `entry-card.tsx` grip, cheap).

### 2. Rewrite `graph-tree.tsx` → `wiki/unorganized-inbox.tsx`
Same `buildGraphTree` clustering (kept), new presentation:
- **Readable rows**: `text-sm` titles, `py-2`, source badge `text-[10px]`, plus a one-line snippet (`text-xs text-muted-foreground line-clamp-1` of `entry.text`) so you can tell entries apart.
- **Real expand/collapse**: chevron column always visible (dot for leaves), list-level `expanded: Set<string>` with collapse-all / expand-all buttons, children-clusters open by default.
- **Header**: "Inbox — N unorganized" count (X of Y when at the 300 cap), client-side filter input on title/text.
- **Preview**: click a row → select; bottom ~40% of the inbox panel shows the existing `EntryPeek` (scrollable, dismissible). Hover shows native tooltip with the title.
- **Drag**: row draggable via shared helpers; `setDragImage` from an off-screen styled template (icon + title + source at readable size) instead of the browser snapshot; row dims while dragging.
- **Inbox is a drop target**: dropping a filed entry back onto the inbox un-files it (`path: null`, keeping its source) — organizing works both directions.
- Keep the `linkedOrganized` filing-hint chips (bumped to `text-[10px]`).

### 3. Restructure `wiki/entry-tree.tsx`
- Replace the mode toggle with the three resizable panels; remove `sidebarMode`.
- Mobile: tree drawer (existing) + inbox Sheet with the same components.

### 4. "What am I moving" affordances
- Fixed top-center pill (pointer-events-none) shown during any entry drag: `Moving "<title>" — drop on a folder`. State via a tiny module store + `useSyncExternalStore` in `lib/drag-entry.ts`.
- Drop targets (tree nodes, source roots, folder cards, content background) get a consistent active style: `ring-2 ring-primary bg-primary/10` + a "Move here" chip.
- Auto-expand: hovering a collapsed tree/folder node during a drag opens it after ~500 ms (dragover timer, cancelled on dragleave/drop).
- Success toast shows the entry **title** (not `id.slice(0,16)`) with an **Undo** action that moves it back to the original source/path.

### 5. Fix `hooks/use-wiki-move.ts`
- Predicate-based invalidation matching the real array keys: `mutate(k => Array.isArray(k) && ["entries-paths","entries-tree","items"].includes(k[0]))` + `mutate(["item", id])`.
- No-op guard: skip the PUT when source+path are unchanged.
- Return the moved entry's title so callers can use it in toasts.

### 6. Minor sizing pass on the structured tree
`wiki-tree-node.tsx` leaf links `text-[11px]` → `text-xs`; keep mono aesthetic otherwise.

## Out of scope (explicit)
- No new DnD dependency (staying native HTML5 to match the whole codebase; @dnd-kit would force rewriting every existing drag source/target). Touch/keyboard covered by "Move to…" picker.
- No multi-select batch move (deferred; the move hook supports it later unchanged).
- No virtualization (filter + 300 cap + lazy tree fetch handle size).
